# Post-mortem — incidents après mises en production sur Payments Gateway

## Impact
Entre avril et juin 2026, plus de la moitié des changes sur Payments Gateway ont été suivis d'un incident sur le même serveur dans les 48 h.

## Cause racine
Les tests de non-régression ne couvrent pas les flux SEPA instantanés ; les changes de type `standard` passent sans revue.

## Actions correctives
1. Reclasser les changes Payments Gateway en type `normal` (revue obligatoire).
2. Ajouter les flux SEPA instantanés à la campagne de non-régression.
3. Suivre le taux d'incidents post-change dans le dashboard « Change risk ».
